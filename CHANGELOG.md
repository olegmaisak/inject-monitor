# CHANGELOG — Inject Monitor

Формат версий: `vMAJOR.FEATURE.BUGFIX (YYYY.MM.DD)` по скиллу `versioning-for-all`.
FEATURE-инкремент = сколько значимых фич, по логу изменений.
Подсистема из нескольких связанных фич = +1 (см. правило подсистем в скилле).

Исторические версии (0.01.00–0.10.00) записаны в старой схеме (X.YZ); при их
приведении к каноническому формату см. скилл `versioning-for-all` и исторический
пункт в скилле Директрисы.

## v0.32.0 (2026.09.22)

**Фичи (+4 поверх v0.28.1):**

1. **Управление сервером из UI** (подсистема: кнопки + POST `/api/server`): в Settings →
   «Server» перед портом появились кнопки **⏹ Stop server** (с confirm — после остановки
   сайт падает до ручного запуска) и **⟳ Restart server** (перезапускает процесс
   через `execv` и ждёт ответа свежего `/api/ping`). Статус операции виден рядом с
   кнопками (`srv-status`). Оба действия требуют токен (POST, как и test-db).
2. **Состояние блоков Settings сохраняется в конфиг** (`settings_open`, массив id
   блоков в порядке Server / Data source / Pairs / Default expansion / Session list /
   Message indentation): переключение блока запоминается в JS, кнопка 💾 Save пишет
   в config.json, при открытии Settings блоки показываются как сохранено.
   Дефолт: свёрнуты все, кроме **Server** (он открыт и по умолчанию, и в отсутствующем
   ключе конфига — backend `_norm_settings_open`).
3. **Реорганизация панели Settings**: порядок блоков по важности для юзера —
   Server / Data source / Injection trigger tag pairs / Default expansion / Session
   list / Message indentation; блоку Server дано новое короткое описание
   («Stop / restart the monitor and set the HTTP port…»); под портом — примечание
   про сброс кэша браузера после обновления с сочетаниями клавиш (Win/Linux:
   Chrome/Edge/Opera и Firefox — Ctrl+F5 / Ctrl+Shift+R; macOS: Chrome/Edge —
   Shift+Cmd+R, Safari — Option+Cmd+R, Firefox — Shift+Cmd+R). В ARCHITECTURE.md
   вынесена рекомендация о порядке блоков при дополнении панели.
4. **Точечное обновление сессии**: ⟳ Refresh и авто-тик больше НЕ перерисовывают
   сессию целиком. `mergeMessages()` → `incrementalRender()`: существующие DOM-узлы
   не трогаются, новые сообщения аппендятся внизу (по id), chips и system prompt
   обновляются in place (только при изменении hash), фильтр переприменяется. Тем же
   путём работает и ⟳ Refresh для открытой сессии (`loadSession` использует merge
   при совпадении id). Сайдбар при перестройке сохраняет scrollTop.

**Без инкремента (косметика):** подзаголовок сайдбара заменён с «diagnosing memory
injections into LLM requests» на «diagnosing harness injections into AI-agent
sessions» (по запросу Олега; терминология: harness, а не memory; agent-сессии, а не
LLM-запросы).

## v0.28.0 (2026.09.21)

**Фичи (+2 поверх v0.27.0):**

1. **Лимит сессий в списке** (config `sessions_limit`, дефолт **50**): сколько последних
   сессий загружать в сайдбар при старте/обновлении. Настраивается в Settings →
   «Session list» (1..500, валидация на PUT), применяется после Save. Выбранная
   (открытая) сессия при обновлении не теряется: `GET /api/sessions?include=<id>`
   добавляет её в конец списка, если она выпала из лимита (дублей нет).
2. **Токен теперь живёт в папке монитора, а не в папке агента**: дефолт `token_file`
   относительный (`inject-monitor-token`) и разворачивается относительно папки
   monitor.py — при установке ещё неизвестно, где будет папка ИИ-агента.
   «Access token file» в конфиге/мастере может быть относительным (папка монитора),
   `~/...` или абсолютным. Миграция: если токен-файл в папке монитора отсутствует,
   а легаси `~/.hermes/inject-monitor-token` есть — значение копируется (токен
   сохраняется, браузерная сессия остаётся валидной). Стартовая инструкция (gate)
   переписана в 3 структурированных шага с ПОДСТАВЛЕННЫМ реальным путём
   (monitor.py подставляет `__TOKEN_FILE_PATH__` в index.html; сам токен по HTTP
   не отдаётся никогда — только путь к файлу).

- Фильтр: «⬇️ only with injections» → «⬇️ Only with injections».

## v0.26.0 (2026.09.20)

**Фичи (+1 подсистема «конфиг-внешний + онбординг» поверх v0.25.0):**

1. **Вынос environment-параметров из кода в config.json**: `db_path` (путь к
   state.db Hermes, был зашит в `~/.hermes/state.db`), `token_file` (файл токена),
   `agentmemory_url` (REST agentmemory; приоритет: config → env `AGENTMEMORY_URL`
   → дефолт). Рядом лежит **config.default.json** — исходник значений по умолчанию
   для большинства пользователей; при первом запуске из него создаётся config.json
   (если файла-дефолта нет — встроенные BUILTIN_DEFAULTS).
2. **Раздел Settings «Data source & connections»**: поля DB path / Token file /
   Agentmemory URL, применяются после Save без рестарта (пути читаются
   пер-запросно с кэшем 3 с). PUT /api/config теперь **сохраняет неизвестные
   ключи** (раньше перезаписывал только известные).
3. **Мастер начальной настройки в одно окно** (нонбург новый юзер): если
   config.json отсутствует или БД не найдена/не читается, сервер НЕ падает —
   запускается и отдаёт `GET /api/status`; UI показывает оверлей-мастер
   (путь БД + Test, token file, agentmemory URL, порт, «Save & continue»).
   Новый `POST /api/test-db` {path} — живая проверка пути.
4. **Счётчик инжектов в списке сессий — фактический**: считает ВСЕ инжекты по
   сессии ровно как парсер в UI (топ-уровень + вложенные, каждое сообщение
   + system prompt + tool-результаты), а не «число сообщений с api_content».
   Кэш по сессии (инвалидация по max(id)/count и изменению пар). Проверено:
   сессия 20260919_235801_93d3d2 показывает 85 inj. (было «3»), сходится с
   парсером на всех 200 сессиях, 0 расхождений.
5. **Эмодзи инжекта 📥 → ⬇️** везде (бейджи «N inj.», фильтр «only with
   injections», заголовки, hint «N chars») — метафора «стрелка вниз = инжект».
6. **Иконки**: рядом с заголовком «Inject Monitor» — icon-light-d1d5dd.png
   (static/logo.png); favicon — icon-blue-75a2d8.png (static/favicon.png).
7. **Исправление Default expansion**: вложенным `<details>` (Tool call details,
   Tool result details, 💭 Reasoning, inj-блоки) ставится **атрибут `open`**, а не
   класс (класс не открывал HTML-details). Плюс EXPAND и indent загружаются из
   /api/config при старте страницы (раньше — только при открытии Settings, из-за
   чего сохранённые состояния игнорировались на загрузке). Раскрытие вложенных
   элементов работает и при свёрнутом родителе.
8. **Сообщение сохранения настроек** упрощено до «✓ Settings saved».

**Багфиксы (попутно):**

- `ThreadingHTTPServer((args.host, args.port))` → `port`: при запуске без флага
  `--port` падал TypeError. Юнит systemd больше не передаёт `--port` — порт
  берётся из config.json.
- `api()` в JS: слияние заголовков (X-Auth-Token + extra) — раньше extra-заголовки
  перезаписывали токен целиком (ломалось PUT / POST мастер/JSON).

## v0.12.0 (2026.09.12)

**Фичи (11 подсистем поверх v0.1.0):**

1. Система пар (парсинг инжектов по парам из config.json + `/api/config` GET+PUT + 
   панель настроек триггерных тегов + поддержка вложенных пар с плоским рендером
   «parent > child»)
2. Универсальный парсинг (парсинг для всех ролей сообщений — не только user +
   system prompt как msg-блок с инжектами; удалён секционный парсинг Hermes)
3. Порт в настройках (config.json `port`, поле в Settings, применяется после
   рестарта сервера)
4. sid вместо model (список сессий: id сессии вместо модели LLM + чипы sid в топ-панели)
5. Ресайз сайдбара (drag-ручка, ширина по умолчанию под полный id)
6. Фильтры (все галочки по умолчанию включены + жёсткий фильтр «только с инжектами»
   + filterbar внутри top-панели, всегда виден)
7. Чип времени последнего сообщения (last_msg в API списка сессий + чип)
8. Единая геометрия сообщений (reasoning первым в теле, инжекты в конце,
   треугольник-маркер раскрытия, все типы msg через `.msg`)
9. Инкрементальный Auto (merge новых записей без сброса состояния панели)
10. Токен из URL (авто-вход по `?token=`)
11. Полный перевод UI на английский (все подписи, гейт, фильтры, настройки)

Попутные багфиксы: иероглифы-артефакты в JS, битая ветка рендера user-сообщений,
кэш пар в тестах.

## v0.10.00 — 2026-09-04 (историческая запись, старая схема)

Первый рабочий релиз + итерация обратной связи Олега.

- **0.01.00** — первый рабочий релиз MVP:
  - backend `monitor.py`: HTTP-сервер (stdlib), read-only чтение `~/.hermes/state.db`,
    токен-авторизация, порт 8092;

    system prompt с разбивкой на секции, инжекты `<memory-context>` из `api_content`.
- **+0.05** — фича: фильтр чекбоксами над содержимым сессии (по умолчанию только записи с инжектом).
- **+0.05** — фича: полный текст memory-context в сворачиваемом блоке (без обрезки).
- Багфиксы в комплекте (не влияют на счёт при фиче-бампе): исправлено «сужение» колонки
  (незакрытый `.mhead` в renderMsg), удалён функционал diff по решению Олега.
